## 1. Overview & Architectural Philosophy

The **Data Normalization & Ingestion Pipeline** acts as an authoritative firewall between messy, semi-structured external files (generated by HR portals, recruitment agencies, or spreadsheet software) and the relational schemas of **InsERT Gratyfikant Nexo Pro** and **ZUS Płatnik (KEDU 5.7 XSD)**.

User-provided files frequently contain formatting defects:
- Excel exports converting 11-digit PESEL numbers into float scientific notation (e.g. `8.4030421022E10`).
- Addresses merged into single strings (e.g. `"ul. Kwiatowa 12A m. 5"`).
- Semicolons embedded inside multiline quoted CSV cells.
- Mixed encodings (UTF-8 with BOM, UTF-8 without BOM, Windows-1250).
- Foreign nationals without Polish citizenship mistakenly entered with Polish ID cards.
- Over-length strings causing SQL truncation or ZUS Płatnik schema rejections.

The normalization pipeline deterministically resolves these issues before data reaches Sfera Business Objects.

## 2. Universal Streaming Ingestion (`UniversalFileLoader.cs`)

### 2.1 File Format Detection (`.xlsx` vs `.csv`)

`UniversalFileLoader` determines the parsing strategy based on the file extension:

```csharp
// Assembly: HrAppka_Import_Pracowników.dll
// Class: UniversalFileLoader
public List<PracownikImportRow> Load(string filePath)
{
    if (string.IsNullOrWhiteSpace(filePath))
        throw new ArgumentException("Ścieżka do pliku nie może być pusta.", nameof(filePath));

    if (!File.Exists(filePath))
        throw new FileNotFoundException($"Nie odnaleziono pliku: {filePath}", filePath);

    string ext = Path.GetExtension(filePath).ToLowerInvariant();
    List<IReadOnlyList<string>> rawRows;

    if (ext == ".csv" || ext == ".txt")
    {
        var csvReader = new Rfc4180CsvReader();
        rawRows = csvReader.ReadRows(filePath)
            .Cast<IReadOnlyList<string>>()
            .ToList();
    }
    else if (ext == ".xlsx" || ext == ".xls")
    {
        rawRows = ReadExcelRows(filePath);
    }
    else
    {
        throw new NotSupportedException($"Nieobsługiwany format pliku: {ext}. Obsługiwane formaty: .xlsx, .xls, .csv, .txt");
    }

    return ProcessRawRows(rawRows);
}
```

Excel files are read in streaming mode via `MiniExcel.Query(filePath, useHeaderRow: false, excelType: ExcelType.XLSX)`, avoiding COM interop or large OpenXML DOM memory footprints.

### 2.3 Address Field Sanitization & Noise Scrubbing

In recruitment CSV files, user names or phone numbers frequently infiltrate address columns due to misaligned delimiters. `SanitizeAddressFields` detects and removes these errors:

```csharp
// Assembly: HrAppka_Import_Pracowników.dll
// Class: UniversalFileLoader
public static void SanitizeAddressFields(PracownikImportRow row)
{
    if (string.IsNullOrWhiteSpace(row.Ulica)) return;

    // 1. PIB Infiltration: Check if Street contains the employee's name
    if (!string.IsNullOrWhiteSpace(row.Imie) && 
        row.Ulica.IndexOf(row.Imie.Trim(), StringComparison.OrdinalIgnoreCase) >= 0)
    {
        row.Ulica = string.Empty;
        row.Ostrzezenia += "Usunięto imię pracownika z pola Ulica. ";
    }
    else if (!string.IsNullOrWhiteSpace(row.Nazwisko) && 
             row.Ulica.IndexOf(row.Nazwisko.Trim(), StringComparison.OrdinalIgnoreCase) >= 0)
    {
        row.Ulica = string.Empty;
        row.Ostrzezenia += "Usunięto nazwisko pracownika z pola Ulica. ";
    }

    // 2. Phone Infiltration: Check if Street is actually a telephone number
    if (Regex.IsMatch(row.Ulica, @"^\+?\d[\d\s\-]{7,}\d$"))
    {
        row.Ulica = string.Empty;
        row.Ostrzezenia += "Usunięto numer telefonu z pola Ulica. ";
    }

    // 3. Length Constraints
    if (row.Ulica.Length > ZusSchemaLimits.ZusUlicaMaxLen)
        row.Ulica = row.Ulica.Substring(0, ZusSchemaLimits.ZusUlicaMaxLen).Trim();
}
```

## 3. RFC 4180 Streaming CSV Parser Deep-Dive (`Rfc4180CsvReader.cs`)

### 3.1 Finite State Machine (FSM) Architecture

`Rfc4180CsvReader` processes files character-by-character from a `TextReader` using an FSM:
- State `inQuotes = true`: Commas, semicolons, and CRLFs are treated as literal text within the field.
- State `inQuotes = false`: Delimiters commit the current field; CRLFs commit the current row.

```
       +----------------------- [ Non-Quote Char ] ------------------------+
       |                                                                    |
       v                                                                    |
+-------------+      Quote Char '"'      +-------------+      Quote Char '"'|
|  inQuotes   | -----------------------> |  inQuotes   | -------------------+
|   = false   |                          |   = true    |
+-------------+ <----------------------- +-------------+
       |             Escaped Quote '""'
       |
       +--- Delimiter ---> Commit Field
       +--- CRLF --------> Commit Row
```

---

### 3.2 Multiline Quoted Fields & Escaped Quotes

RFC 4180 mandates that two consecutive double quotes (`""`) represent a single literal quote (`"`):

```csharp
// Assembly: HrAppka_Import_Pracowników.dll
// Class: Rfc4180CsvReader
if (inQuotes)
{
    if (c == '"')
    {
        int next = reader.Peek();
        if (next == '"')
        {
            reader.Read(); // Consume the second escaped quote
            currentField.Append('"');
        }
        else
        {
            inQuotes = false;
        }
    }
    else
    {
        currentField.Append(c);
    }
}
```

---

### 3.3 Delimiter Auto-Detection Heuristic

`DetectDelimiter` reads characters up to the first unquoted newline, counting occurrences of candidate delimiters (`;`, `,`, `\t`, `|`). The delimiter with the highest count is selected, defaulting to `;` (standard for Polish regional settings).

---

### 3.4 Encoding Probing & Multibyte UTF-8 Boundary Protection

When reading a 4096-byte sample without a BOM, reading cuts off at an arbitrary byte. If the cutoff splits a multibyte UTF-8 sequence (`110xxxxx`, `1110xxxx`, `11110xxx`), strict UTF-8 decoding throws a false `DecoderFallbackException`.

`AdjustLengthForIncompleteTrailingUtf8` rewinds the buffer before strict decoding:

```csharp
// Assembly: HrAppka_Import_Pracowników.dll
// Class: Rfc4180CsvReader
private static int AdjustLengthForIncompleteTrailingUtf8(byte[] buffer, int length, bool isEndOfFile)
{
    if (isEndOfFile || length <= 0) return length;

    int maxLookback = Math.Min(4, length);
    for (int i = 1; i <= maxLookback; i++)
    {
        byte b = buffer[length - i];
        if ((b & 0x80) == 0) break; // ASCII byte

        if ((b & 0xC0) == 0xC0) // Leading multi-byte header
        {
            int expectedSequenceLength;
            if ((b & 0xE0) == 0xC0) expectedSequenceLength = 2;
            else if ((b & 0xF0) == 0xE0) expectedSequenceLength = 3;
            else if ((b & 0xF8) == 0xF0) expectedSequenceLength = 4;
            else break;

            int presentBytes = i;
            if (presentBytes < expectedSequenceLength)
            {
                // Incomplete multi-byte sequence cut off at buffer limit
                return length - presentBytes;
            }
            break;
        }
    }
    return length;
}
```

## 5. ZUS Płatnik KEDU vs Gratyfikant Nexo Schema Limits (`ZusSchemaLimits` in `AddressNormalizer.cs`)

### 5.1 The Length Discrepancy Problem

Gratyfikant Nexo SQL tables often permit larger columns than ZUS Płatnik KEDU 5.7 XSD schemas. For example, `Ulica` is stored in SQL as `nvarchar(64)`, but ZUS KEDU schema type `t_Ulica_30` enforces a strict maximum of **30 characters**. If an address is 45 characters long, Nexo saves it, but ZUS Płatnik rejects the exported declaration package.

`ZusSchemaLimits` enforces the strict lower bound.

## 6. Offline SQLite Address Enrichment (`AddressEnrichmentService.cs`)

### 6.1 Multi-Stage File Discovery for `DaneAdresowe.db`

The service locates the official Nexo SQLite dictionary via four probing paths:
1. `AppDomain.CurrentDomain.BaseDirectory\DaneAdresowe\DaneAdresowe.db`
2. `Path.GetDirectoryName(Assembly.GetExecutingAssembly().Location)\DaneAdresowe\DaneAdresowe.db`
3. Parent folder: `..\DaneAdresowe\DaneAdresowe.db`
4. Global Nexo deployment cache: `%LOCALAPPDATA%\InsERT\Deployments\Nexo\*\Binaries\DaneAdresowe\DaneAdresowe.db`

---

### 6.2 Concurrent Caching Architecture

Lookups are cached in a `ConcurrentDictionary<string, AddressEnrichmentResult?>` using `StringComparer.OrdinalIgnoreCase`. Repeated lookups for the same postal code incur zero disk I/O.

---

### 6.3 Fail-Safe Offline Execution

If `DaneAdresowe.db` is missing or corrupt, `AddressEnrichmentService` returns `null` without throwing exceptions, allowing the import to proceed using only the data provided in the source file.

## 7. Bank Clearing & Account Verification (`BankClearingResolver.cs`)

### 7.1 8-Digit KNR Sort Code Extraction

The Polish National Bank Account (*NRB*) structure embeds an 8-digit clearing number (*KNR*) at positions 2 through 9:
$$\text{NRB} = \text{KK} \underbrace{\text{BBBB}}_{\text{Institution}} \underbrace{\text{OOOO}}_{\text{Branch}} \text{NNNNNNNNNNNNNNNN}$$

`ExtractSortCode` strips `"PL"`, spaces, and dashes, extracting the 8-digit clearing identifier.

---

### 7.2 Bank Identification Directory

The resolver identifies commercial and cooperative institutions:
- `1010` -> Narodowy Bank Polski
- `1020` -> Powszechna Kasa Oszczędności Bank Polski SA (PKO BP)
- `1050` -> ING Bank Śląski SA
- `1090` -> Santander Bank Polska SA
- `1140` -> mBank SA
- `1160` -> Bank Millennium SA
- `1240` -> Bank Pekao SA
- `1600` -> BNP Paribas Bank Polska SA
- `2480` / `2490` -> Alior Bank SA
- First digit `'8'` -> `"Bank Spółdzielczy (zrzeszenie SGB)"`
- First digit `'9'` -> `"Bank Spółdzielczy (zrzeszenie BPS)"`

---

### 7.3 ISO 7064 Modulo 97 IBAN Checksum Verification

Validates the checksum of Polish and foreign IBAN accounts according to ISO 7064 Modulo 97:
$$\text{rearranged} = \text{BBBBBBBBNNNNNNNNNNNNNNNN} + 2521 + \text{KK}$$
$$\text{rearranged} \pmod{97} \equiv 1$$

## 8. ZUS Citizenship Management (`ZusCitizenshipManager.cs`)

### 8.1 `Obywatelstwa_ZUS.csv` Dictionary Ingestion

The service loads the official ZUS dictionary containing:
- ISO 3166 alpha-2 country codes (`PL`, `UA`, `BY`, `GE`).
- Polish country names (`Polska`, `Ukraina`, `Białoruś`).
- Official ZUS citizenship adjectives (`polskie`, `ukraińskie`, `białoruskie`).

Loaded strictly in UTF-8 with BOM awareness.

---

### 8.2 5-Tier Matching Hierarchy & Diacritic Stripping

1. **Exact Adjective Match**: `"ukraińskie"` -> `UA`
2. **Exact Country Match**: `"Ukraina"` -> `UA`
3. **ISO Alpha-2 Match**: `"UA"`, `"PL"`
4. **Colloquial Noun**: `"Polak"`, `"Ukrainiec"`
5. **Diacritic-Stripped Match**: `RemoveDiacritics("ukrainskie")` matches `"ukraińskie"`.

### 8.3 The Mandatory "No Silent Fallback to Poland" Rule

> **Strict Invariant**: If an input nationality cannot be resolved against the dictionary, `MatchEntry` **MUST return `null`**. It is strictly forbidden to default to Poland (`PL`). Defaulting foreign workers to Poland causes severe tax errors and ZUS reporting non-compliance.

### 9.2 Document Number Sanitization for ZUS KEDU

Strips non-alphanumeric characters, converts to uppercase, and truncates to **9 characters**:

```csharp
public static string SanitizeDocumentNumber(string? rawNumber, int maxLength = 9)
{
    if (string.IsNullOrWhiteSpace(rawNumber)) return string.Empty;
    string cleaned = Regex.Replace(rawNumber, @"[^A-Za-z0-9]", "").ToUpperInvariant();
    return cleaned.Length > maxLength ? cleaned.Substring(0, maxLength) : cleaned;
}
```

## 10. PESEL Helper & Scientific Notation Restoration (`PeselHelper.cs`)

When exporting data to CSV, Microsoft Excel frequently formats 11-digit PESEL numbers as floating-point scientific notation:
`"8.4030421022E10"`

`NormalizePesel` detects the `E` exponent, parses the float, converts to an integer string, and restores any stripped leading zero:

```csharp
// Assembly: HrAppka_Import_Pracowników.dll
// Class: PeselHelper
public static string NormalizePesel(string? rawPesel)
{
    if (string.IsNullOrWhiteSpace(rawPesel)) return string.Empty;
    string trimmed = rawPesel.Trim();

    if (trimmed.IndexOf('E', StringComparison.OrdinalIgnoreCase) >= 0 &&
        double.TryParse(trimmed, NumberStyles.Float, CultureInfo.InvariantCulture, out double dVal))
    {
        long longVal = (long)Math.Round(dVal);
        return longVal.ToString("D11"); // Pads leading zeros up to 11 digits
    }

    return Regex.Replace(trimmed, @"[^\d]", "");
}
```
